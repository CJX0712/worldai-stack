# ADR-001：模块按 Protocol 注入划分，默认零依赖真实实现

- 状态：已采纳
- 作者：晨星
- 日期：2026-09-24

## 背景

目标是交付一套端到端可运行的 AI 系统，要求：可在干净环境一键复现、离线可验证、
各模块可独立验证且能协同成链。若每个模块直接依赖具体第三方库（torch / faiss /
fastembed / llama.cpp），则默认验证必须下载模型/装重型依赖，复现成本高且脆弱。

## 决策

1. **单一职责 + 依赖反转**：每个功能模块只声明一个 `@runtime_checkable` Protocol；
   模块之间只依赖 Protocol，不依赖具体实现。
2. **组合根注入**：`worldai.config.build_stack` 是唯一装配点，按 `Settings`（环境变量）
   实例化并注入全部实现。
3. **默认零依赖真实实现**：哈希嵌入 / 内存精确余弦 / IDF 词法 BM25 / IDF 余弦重排 /
   确定性 Mock LLM，全部纯标准库，保证默认链路离线可验证。
4. **生产实现惰性加载**：FastEmbed / FAISS / Rank-BM25 / llama.cpp / Ollama 仅在被选中
   且首次调用时才加载，构造阶段不触网/不下载。

## 后果

- ✅ `git clone && pip install -r requirements.lock.txt && python scripts/verify.py`
  在裸 CPython（零第三方）上也能跑通默认链路（除 REST 服务需 fastapi/uvicorn）。
- ✅ 每个模块可用 fake/默认实现独立单测；生产实现仅测接线与离线检索。
- ⚠️ 默认实现的检索精度低于生产神经网络嵌入，但作为「可复现基线 + 守护测试」足够；
  生产精度由 `WORLDAI_*` 切换获得。

# ADR-002：默认实现必须是真实实现，而非占位 stub

- 状态：已采纳
- 作者：晨星
- 日期：2026-09-24

## 背景

早期直觉可能用 `MockLLM` 返回固定文本、`HashEmbedder` 返回随机向量来「跑通」。但这样
验证毫无意义：检索指标、接地指标、跨模块链路都是假的，真回归无法被发现。

## 决策

每个外部端口都配一个**零依赖真实实现**：
- 嵌入：BLAKE2b 有符号哈希 + 中文 bigram（余弦相似度真实反映词法重叠）
- 向量库：精确余弦（非近似）
- 稀疏/重排：BM25 + Robertson 非否定 IDF（真实词法得分）
- 生成：确定性 Mock LLM 真驱动 ReAct 循环并抽取式回答

「默认配置 = 被持续验证的配置」，使 `verify` 的全绿成为真实能力的证据。

## 后果

- ✅ 默认链路下 doc_hit_rate / doc_mrr / groundedness 均为真实可测指标。
- ✅ 切换生产实现后，可在同测试集上对比精度提升。
